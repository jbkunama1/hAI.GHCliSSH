🚀 hAI.GHCliSSH

GitHub Copilot CLI in a browser-based terminal (ttyd) — one docker run away. No separate SSH server needed, no local install required.

📖 Overview

This project provides a single Docker container that publishes a browser-based terminal (via ttyd) and has GitHub Copilot CLI pre-installed. Start the container, open http://<host>:8833 in a browser and work directly with copilot and other commands — just like an SSH session, but without a separate SSH server.

🏗️ Architecture

LayerDescription
Base imagetsl0922/ttyd:latest — ships ttyd and all terminal-over-HTTP plumbing
Copilot CLIInstalled via GitHub's official script: curl -fsSL https://gh.io/copilot-install | bash
ttyd listenerPort 8833 inside the container, mapped to the host
Workspace/workspace — working directory inside the container

🛠️ Install

git clone https://github.com/jbkunama1/hAI.GHCliSSH.git
cd hAI.GHCliSSH
docker build -t copilot-ttyd .

🚀 Run

docker run --rm -it \
  -p 8833:8833 \
  --name copilot-ttyd \
  copilot-ttyd
Tip: To persist your work, add -v copilot-workspace:/workspace. To retain Copilot credentials, add -v copilot-config:/home/copilot/.copilot.

📦 Pre-built GHCR image

A pre-built image is published to GitHub Container Registry for every push to main:

ghcr.io/jbkunama1/hai.ghclissh:main
Note: The package is currently private. To pull it you must either make the package public on GitHub or authenticate your container runtime (see Deploy to Portainer).
docker pull ghcr.io/jbkunama1/hai.ghclissh:main

For a private package, log in first:

echo $GITHUB_TOKEN | docker login ghcr.io -u jbkunama1 --password-stdin

where GITHUB_TOKEN is a PAT with the read:packages scope.

🐳 Docker Compose

The standard deployment uses docker-compose.yml, which references the GHCR image:

services:
  copilot-terminal:
    image: ghcr.io/jbkunama1/hai.ghclissh:main
    container_name: hAI.GHCliSSH
    ports:
      - "8833:8833"
    volumes:
      - copilot-config:/home/copilot/.copilot
    restart: unless-stopped

volumes:
  copilot-config:
docker compose up -d

The copilot-config volume persists your Copilot authentication and configuration between restarts.

⚓ Deploy to Portainer

  1. In Portainer open Stacks → Add stack.
  2. Choose the Repository tab.
  3. Enter the repository URL: https://github.com/jbkunama1/hAI.GHCliSSH.git
  4. Set the Compose path to docker-compose.yml.
  5. Select the branch to deploy from (main).
  6. Click Deploy the stack and wait for the image to be pulled.

Deploy the stack directly from the repository. The following environment variables are available (set them in the Environment variables field when creating the stack):

VariablePurposeExample
MCP_SERVER (optional)MCP server for Copilot CLIAnythingMCP

The stack serves on port 8833, mounts the copilot-config volume for persistent Copilot configuration and attaches the container to the external Docker network highfishNetwork (must already exist in Portainer/Docker). After the first start, run copilot login once in the web terminal — the token stays in the volume.

Private package: If the GHCR package is private, add a registry credential in Portainer first. Create a PAT with the read:packages scope, add it under Registries (GitHub Container Registry, user jbkunama1), and select it in the stack's registry dropdown before deploying.

🌐 Browser Access

Open http://localhost:8833 (or http://<host-ip>:8833 from another machine) to get a full TTY served over HTTP by ttyd.

🤖 Using Copilot CLI

copilot
copilot -p "create a bash script that cleans up my git repo"

On first launch Copilot CLI asks whether you trust the current directory and prompts you to authenticate via the GitHub login flow.

🛡️ Security & Networking

  • Do not expose port 8833 to the public internet without additional authentication. A reverse proxy with Basic Auth, OAuth or a VPN is strongly recommended — the terminal has full access to the container.
  • For classroom or local test setups a LAN-only binding plus firewall rules is usually sufficient.
  • Persistence of authentication: mount a volume for the Copilot config directory (e.g., -v copilot-config:/home/copilot/.copilot). Note that without a system keychain, credentials may be stored in plaintext.
